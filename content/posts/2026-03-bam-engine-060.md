**BAM Engine 0.6.0** consolidates market-matching logic into vectorized
operations, delivering ~30% faster simulations with no change to model
behavior.

<!--more-->

## Vectorized Market Matching

Previous releases modeled each market round as a sequence of fine-grained
event classes — one for posting, matching, negotiating, transacting, and
settling. Version 0.6.0 collapses these five classes into three unified
market-round events — one each for labor, credit, and goods — that handle the
full matching cycle in a single vectorized pass.

This means fewer Python-level loops and more work pushed into batch NumPy
operations where it belongs.

## ~30% Faster Simulations

The consolidation eliminates per-event overhead and lets NumPy process entire
agent arrays in one call. Across the standard benchmark suite, wall-clock
simulation time drops by roughly 30%.

## Breaking Changes

- **5 event classes removed.** The individual posting, matching, negotiating,
  transacting, and settling events have been replaced by unified market-round
  events (`LaborMarketRound`, `CreditMarketRound`, `GoodsMarketRound`).
- **`<->` pipeline syntax discontinued.** Use the standard pipeline
  configuration instead.

If you rely on subclassing or overriding any of the removed events, see the
[migration guide](https://bam-engine.readthedocs.io/en/latest/migration.html)
for the mapping from old to new classes.

## No Change to Model Behavior

The refactoring is purely internal. Given the same configuration and random
seed, v0.6.0 produces identical simulation outputs to v0.5.x. All validation
and calibration baselines continue to pass.

## Upgrading

```bash
pip install --upgrade bamengine
```

If your code only uses the public `Simulation` API and built-in extensions, no
changes are required. If you reference removed event classes or the `<->`
syntax, consult the
[migration guide](https://bam-engine.readthedocs.io/en/latest/migration.html).
